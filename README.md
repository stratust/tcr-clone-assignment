# TCR Clone Assignment

An R pipeline for assigning TCR (T Cell Receptor) clonotypes from **Cell Ranger VDJ/multi** output (10x Genomics), with proper handling of dual α/β chains per cell barcode.

**Input:** `filtered_contig_annotations.csv` (Cell Ranger multi or VDJ)
**Output:** A dataframe with one row per cell barcode and a `clone_id` column, plus optional CSVs and plots.

## Biological Background

### V(D)J Recombination and TCR Structure

T cell receptors (TCRs) are heterodimeric proteins composed of an **α (alpha) chain** and a **β (beta) chain**. Each chain is generated by V(D)J recombination during thymic development:

- **α chain**: V gene segment + J gene segment (no D segment)
- **β chain**: V gene segment + D gene segment + J gene segment

The junctional region (V-CDR3-J) is the most variable part — it's the **CDR3 loop** that directly contacts the peptide-MHC complex. Two T cells with the same CDR3β (and Vβ/Jβ) are considered the same **clonotype** — they likely descend from a common T cell that underwent the same recombination event.

### The Dual-Chain Problem

In single-cell VDJ sequencing, we frequently observe **more than one productive α and/or β chain** for the same cell barcode. This can arise from two causes:

#### 1. Allelic Inclusion (True Biology)

During thymic selection, the **TCRα locus** rearranges on both chromosomes. Unlike TCRβ — which undergoes rigorous allelic exclusion — TCRα frequently escapes negative feedback before one allele is silenced. The result:

- **~25–35% of mature T cells** carry **two productive α chains** (dual-TCRα)
- **~3%** carry **two productive β chains** (dual-TCRβ, rare — α:β ratio ≈ 10:1)

These dual-TCR cells are biologically relevant: they may have altered antigen affinity, participate in cross-reactivity, and have been implicated in autoimmunity and tolerance.

#### 2. Technical Artifacts

| Artifact | Cause | Diagnosis |
|----------|-------|-----------|
| **Doublets/multiplets** | 2+ cells captured in the same GEM (gel bead-in-emulsion) | High dual-α rate (>50%) |
| **Ambient RNA** | Cell-free mRNA contaminating the barcode | Secondary chain with very low UMI |
| **Index hopping** | Index swapping during sequencing | Random pattern, not reproducible |

### How This Pipeline Handles Dual Chains

The pipeline **does not discard** dual-chain cells. Instead, it:

1. **Ranks** all chains per barcode by UMI count (descending)
2. Designates the highest-UMI chain as **primary** and the second-highest as **secondary**
3. **Flags** the secondary chain as **trusted dual** (likely real biology) or **untrusted** (likely artifact) based on:
   - **UMI ratio**: secondary ≥ 10% of primary's UMI
   - **Absolute UMI**: secondary ≥ 1 UMI (configurable)
4. **Assigns clonotypes** using only the **primary** chains (standard practice)
5. **Annotates** which cells have trusted dual chains, preserving this information for downstream analysis

## Pipeline Overview

```
filtered_contig_annotations.csv (Cell Ranger multi/VDJ output)
         │
         ▼
   ┌─────────────────┐
   │  1. Filtering    │  productive + high_confidence + is_cell + TRA/TRB
   │                  │  + min_umi + min_read thresholds
   └────────┬────────┘
            ▼
   ┌─────────────────┐
   │  2. Ranking      │  For each barcode, rank chains by UMI (desc)
   │     by UMI       │  primary = rank 1, secondary = rank 2
   └────────┬────────┘
            ▼
   ┌─────────────────┐
   │  3. Dual-TCR     │  Classify secondary chains as:
   │     filtering    │  trusted_dual = TRUE / FALSE
   │                  │  (UMI ratio ≥ 10% AND absolute UMI ≥ threshold)
   └────────┬────────┘
            ▼
   ┌─────────────────┐
   │  4. Clone        │  Define clones by CDR3 + V/J gene
   │     assignment   │  Assign clone IDs (clon1, clon2, ...) by frequency
   └────────┬────────┘
            ▼
   ┌─────────────────┐
   │  5. QC + Plots   │  Shannon diversity, Pielou evenness,
   │                  │  clone size distribution, dual-TCR rates
   └─────────────────┘
```

## Step-by-Step: How It Works

### Step 1: Loading & Filtering Contigs

**Function:** `load_contigs(contig_csv, min_umi = 1, min_read = 1)`

Reads `filtered_contig_annotations.csv` (or `all_contig_annotations.csv`) and applies the following filters:

| Filter | What it removes | Why |
|--------|----------------|-----|
| `is_cell == TRUE` | Contigs not assigned to a cell barcode (background/background RNA) | Cell Ranger flags cell-associated vs. background contigs |
| `high_confidence == TRUE` | Low-confidence assemblies | Contigs with poor assembly quality are unreliable |
| `productive == TRUE` | Non-productive rearrangements (out-of-frame, stop codons, etc.) | Only productive rearrangements produce functional TCR proteins |
| `chain %in% c("TRA", "TRB")` | TRG, TRD, IGH, IGL, IGK chains | This pipeline focuses on αβ T cells; γδ T cells and B cells are excluded |
| `umis >= min_umi` | Contigs with very few UMIs | Low UMI = low confidence that the chain is real (default = 1, i.e., no additional filtering for filtered_contig_annotations.csv which is already QC'd by Cell Ranger) |
| `reads >= min_read` | Contigs with very few reads | Same principle as UMI filter (default = 1) |

> **Note:** When using `filtered_contig_annotations.csv` (the recommended input), Cell Ranger has **already** applied the first four filters. The `min_umi` and `min_read` defaults of `1` mean "trust Cell Ranger's QC." If you use `all_contig_annotations.csv` instead, **raise these thresholds** (e.g., `min_umi = 5, min_read = 20`) to filter out low-quality contigs that Cell Ranger excluded.

**What you get:** A filtered data.frame of productive, high-confidence, cell-associated TRA/TRB contigs.

**Diagnostic messages:**
```
>>> Loading contig annotations: vdj_t/outs/filtered_contig_annotations.csv
  Raw: 12453 rows, columns: barcode, is_cell, contig_id, high_confidence, length, chain, v_gene, d_gene, j_gene, c_gene, full_length, productive, fwr1, fwr1_nt, cdr1, cdr1_nt, fwr2, fwr2_nt, cdr2, cdr2_nt, fwr3, fwr3_nt, cdr3, cdr3_nt, fwr4, fwr4_nt, reads, umis, raw_clonotype_id, raw_consensus_id, exact_subclonotype_id
  After filters: 8721 rows
  8721 productive contigs from 3247 unique cell barcodes
```

### Step 2: Ranking Chains per Barcode

**Function:** `rank_chains(contigs)`

A single cell barcode can have multiple TRA and/or TRB contigs. This step ranks them:

1. **Group** contigs by `barcode` + `chain` (e.g., all TRA contigs for barcode X, all TRB contigs for barcode X)
2. **Rank** by `umis` descending within each group
3. **Primary** chain = highest UMI (rank 1)
4. **Secondary** chain = second-highest UMI (rank 2), if it exists

The function also counts chains per barcode and classifies each cell:

| `chain_status` | Meaning | Expected frequency |
|----------------|---------|-------------------|
| `single` | One TRA + one TRB (no dual chains) | ~65–70% |
| `dual_alpha` | Two+ productive TRA chains | ~25–35% |
| `dual_beta` | Two+ productive TRB chains | ~3% |
| `dual_alpha_beta` | Both dual α AND dual β | Rare |

If dual-α rate exceeds 50%, the pipeline issues a **WARNING** — this likely indicates doublet contamination.

**What you get:** Three dataframes:
- `primary` — one row per barcode × chain type (rank 1), with `_prim` suffix on columns
- `secondary` — one row per barcode × chain type (rank 2, if exists), with `_sec` suffix
- `n_chains` — one row per barcode with chain counts and `chain_status`

---

### Step 3: Dual-TCR Filtering

**Function:** `filter_dual_tcr(primary, secondary, min_ratio = 0.1, min_abs_umi = 1)`

Not all dual-chain cells are real. A secondary chain with 2 UMIs when the primary has 200 is likely ambient RNA contamination, not a true second TCR. This step classifies each secondary chain as **trusted** or **untrusted**:

**Criteria for `trusted_dual = TRUE`:**

1. **UMI ratio** ≥ `min_ratio` (default 10%): `umis_sec / umis_prim >= 0.1`
2. **Absolute UMI** ≥ `min_abs_umi` (default 1): `umis_sec >= 1`

Both criteria must be met simultaneously.

**What gets excluded (flagged as `trusted_dual = FALSE`):**
- Secondary chains with very low UMI relative to the primary (likely ambient RNA)
- Secondary chains with extremely low absolute UMI counts

> **Important:** Excluded secondary chains are **not deleted** from the data. They are flagged. The primary chain is always retained for clone assignment regardless of dual-chain status.

**The 10% threshold** is an empirical consensus widely used in single-cell VDJ analysis to distinguish genuine dual-chain expression from ambient RNA contamination. It is not tied to a single publication but reflects standard practice in the field (see e.g., 10x Genomics technical documentation and scRepertoire vignettes).

---

### Step 4: Clone Assignment

**Function:** `build_clones(primary, secondary_filtered, clone_definition = "TRB")`

This is where clonotypes are defined. The pipeline supports three definitions:

| Mode | Clone key formula | Recommended use |
|------|-------------------|-----------------|
| `TRB` *(default)* | `cdr3_TRB` + `v_gene_TRB` + `j_gene_TRB` | Standard in the field; TRB CDR3 is the primary determinant of antigen specificity |
| `TRA_TRB` | `cdr3_TRA` + `v_gene_TRA` + `cdr3_TRB` + `v_gene_TRB` | More stringent; distinguishes cells that share TRB but differ in TRA |
| `TRB_cdr3_only` | `cdr3_TRB` (amino acid only) | Most permissive; useful for exploratory analysis or when V/J gene info is unreliable |

#### How clones are formed (step by step):

1. **Pivot to wide format:** Convert the primary chains from long (one row per barcode × chain) to wide (one row per barcode, with separate columns for TRA and TRB). This gives one row per **cell**.

2. **Compute clone key:** For each cell, concatenate the relevant CDR3 + gene fields into a string (e.g., `"CASSLAPGATNEKLFF|TRBV2|TRBJ1-2"`).

3. **Count and rank clonotypes:** Group all cells by clone key, count how many cells share each key, and sort descending by frequency.

4. **Assign clone IDs:** The most frequent clone key gets `clon1`, the second most frequent gets `clon2`, and so on. Clone IDs are always ordered by descending frequency.

5. **Annotate dual chains:** Add boolean columns `has_dual_alpha` and `has_dual_beta` indicating whether this cell has a trusted secondary chain.

#### What this means in practice:

- **Two cells with the same TRB CDR3 + Vβ + Jβ = same clone** (in `TRB` mode). They share the same antigen specificity determinant.
- **A cell with no TRB chain** (only TRA recovered) will have `NA` in the clone key fields and will be assigned its own singleton clone.
- **Clone IDs are arbitrary labels** — `clon1` is simply the most frequent, not biologically special.
- **Clone definition matters:** `TRB` mode may merge cells that differ in TRA (which could have different fine specificities). Use `TRA_TRB` if this matters for your analysis.

---

### Step 5: QC Summary

**Function:** `qc_summary(cells_df, n_chains, clonotypes)`

Reports:

| Metric | Description |
|--------|-------------|
| **Cells with α+β** | Cells where both TRA and TRB were recovered |
| **Cells with α only** | Only TRA recovered (TRB dropped or not captured) |
| **Cells with β only** | Only TRB recovered |
| **Dual-α rate** | % of cells with 2+ TRA chains (expected: 25–35%) |
| **Dual-β rate** | % of cells with 2+ TRB chains (expected: ~3%) |
| **Total clonotypes** | Number of distinct clones |
| **Singletons** | Clones with exactly 1 cell (% of total clones) |
| **Top 10 clone share** | % of cells in the 10 largest clones |
| **Shannon diversity** | $H' = -\sum p_i \ln(p_i)$ — higher = more diverse repertoire |
| **Pielou evenness** | $J' = H' / \ln(S)$ — 0 = dominated by one clone, 1 = perfectly even |

## The `assign_clones()` Output Dataframe

`assign_clones()` is the core function — it takes filtered contigs and returns a single dataframe with one row per **cell barcode** and a `clone_id` column.

```r
contigs <- load_contigs("vdj_t/outs/filtered_contig_annotations.csv")
clones_df <- assign_clones(contigs, clone_def = "TRB")
```

### Column descriptions

The output is in **wide format**: one row per cell barcode, with primary TRA and TRB chains as separate columns.

| Column | Type | Description |
|--------|------|-------------|
| `barcode` | chr | Cell barcode (unique cell identifier). In batch mode, prefixed with sample ID (e.g., `CTRL_AAACCTGAGAAACCGC-1`). |
| `chain_prim_TRA` | chr | Always `"TRA"` if a primary TRA chain exists, otherwise `NA` |
| `v_gene_prim_TRA` | chr | TRA V gene (e.g., `TRAV6-1`) |
| `d_gene_prim_TRA` | chr | TRA D gene — always `NA` (α locus has no D segment) |
| `j_gene_prim_TRA` | chr | TRA J gene (e.g., `TRAJ26`) |
| `c_gene_prim_TRA` | chr | TRA constant gene (always `TRAC`) |
| `cdr3_prim_TRA` | chr | CDR3 amino acid sequence of primary α chain (e.g., `CALSGGYSSNTGKLIF`) |
| `cdr3_nt_prim_TRA` | chr | CDR3 nucleotide sequence of primary α chain |
| `umis_prim_TRA` | dbl | UMI count for primary α chain |
| `reads_prim_TRA` | dbl | Read count for primary α chain |
| `chain_prim_TRB` | chr | Always `"TRB"` if a primary TRB chain exists, otherwise `NA` |
| `v_gene_prim_TRB` | chr | TRB V gene (e.g., `TRBV2`) |
| `d_gene_prim_TRB` | chr | TRB D gene (e.g., `TRBD1`) — may be `NA` if not annotated |
| `j_gene_prim_TRB` | chr | TRB J gene (e.g., `TRBJ1-2`) |
| `c_gene_prim_TRB` | chr | TRB constant gene (`TRBC1` or `TRBC2`) |
| `cdr3_prim_TRB` | chr | CDR3 amino acid sequence of primary β chain (e.g., `CASSLAPGATNEKLFF`) |
| `cdr3_nt_prim_TRB` | chr | CDR3 nucleotide sequence of primary β chain |
| `umis_prim_TRB` | dbl | UMI count for primary β chain |
| `reads_prim_TRB` | dbl | Read count for primary β chain |
| `clone_id` | chr | Clonotype ID assigned by frequency rank (`clon1` = most frequent, `clon2` = second, etc.) |
| `n` | int | Number of cells in this clone |
| `has_dual_alpha` | lgl | `TRUE` if this cell has a trusted secondary TRA chain (dual-TCRα) |
| `has_dual_beta` | lgl | `TRUE` if this cell has a trusted secondary TRB chain (dual-TCRβ) |

### What each column tells you

- **`clone_id`** — The main output. Cells sharing the same `clone_id` are considered the same clonotype. `clon1` is the largest clone.
- **`n`** — Clone size. If `n = 142`, this clone has 142 cells. Useful for computing clone frequencies: `frequency = n / sum(n)`.
- **`cdr3_prim_TRB`** — The CDR3 amino acid sequence of the β chain. This is the key specificity determinant. Two cells with identical CDR3β (and same Vβ/Jβ) are the same clone.
- **`has_dual_alpha` / `has_dual_beta`** — Whether this cell has a **trusted** second chain. These cells are biologically interesting — they express two different TCRs and may have altered specificity.
- **`umis_prim_*`** — Expression level of each chain. Useful for quality assessment: very low UMIs may indicate poor recovery.

### What is NOT in the output (and why)

| Excluded | Reason |
|----------|--------|
| Non-cell contigs (`is_cell = FALSE`) | Background RNA, not from a real cell |
| Low-confidence contigs | Unreliable assembly |
| Non-productive rearrangements | Cannot produce a functional TCR protein |
| Non-TRA/TRB chains (TRG, TRD, IGH, etc.) | Pipeline focuses on αβ T cells |
| Secondary chains flagged `trusted_dual = FALSE` | Likely artifacts (ambient RNA, low UMI) — still saved in `dual_chain_filtered.csv` for inspection, but not used for clone assignment |
| Rank 3+ chains | If a barcode has 3+ TRA chains, only the top 2 are considered. Rank 3+ is almost always artifact. |

## Batch Mode: Multiple Samples

For cross-sample comparisons, use `load_contigs_batch()` and `run_tcr_pipeline_batch()`:

```r
source("tcr_clone_assignment.R")

samples <- list(
  CTRL    = "ctrl/vdj_t/outs/filtered_contig_annotations.csv",
  PATIENT = "patient/vdj_t/outs/filtered_contig_annotations.csv"
)

results <- run_tcr_pipeline_batch(
  sample_list = samples,
  output_dir  = "tcr_results_batch",
  clone_def   = "TRB"
)
```

### How batch mode works

1. **Barcode prefixing:** Each barcode is prefixed with the sample name from the list key (e.g., `CTRL_AAACCTGAGAAACCGC-1`). This is **critical** — 10x barcodes come from a shared ~3.4M whitelist, so the same barcode sequence in different runs refers to different physical cells. Without prefixing, two cells from different samples would be treated as the same cell.

2. **Combined analysis:** All contigs are merged into a single data.frame with a `sample` column, enabling:
   - Cross-sample clonotype overlap analysis
   - Per-sample diversity metrics
   - Detection of shared/public clonotypes

3. **Additional batch outputs:** Per-sample summary table, cross-sample overlap table, and batch-specific plots.

### Batch output: `per_sample_summary.csv`

| Column | Description |
|--------|-------------|
| `sample` | Sample ID |
| `n_cells` | Total cells in this sample |
| `n_clones` | Number of distinct clonotypes |
| `top_clone_n` | Number of cells in the largest clone |
| `top_clone_pct` | Largest clone as % of sample cells |

### Batch output: `cross_sample_overlap.csv`

Lists clonotypes found in 2+ samples — these are **shared/public clonotypes** that may indicate a common antigen response.

| Column | Description |
|--------|-------------|
| `clone_id` | Clonotype ID |
| `n_samples` | Number of samples sharing this clone |
| `samples` | Comma-separated sample names |

## Parameters

| Parameter | Default | Description | When to adjust |
|-----------|---------|-------------|----------------|
| `contig_csv` | *(required)* | Path to `filtered_contig_annotations.csv` (recommended) or `all_contig_annotations.csv` | Use `filtered` for Cell Ranger multi; `all` only for legacy VDJ-only runs |
| `clone_def` | `"TRB"` | Clone definition mode | `"TRA_TRB"` for more stringency; `"TRB_cdr3_only"` for exploration |
| `min_umi` | `1` | Minimum UMI per contig | Raise to `3–5` if using `all_contig_annotations.csv`; keep at `1` for `filtered_contig_annotations.csv` (already QC'd) |
| `min_read` | `1` | Minimum reads per contig | Same as above |
| `min_ratio` | `0.1` | Minimum UMI ratio (secondary/primary) | `0.05` to capture more dual-TCRs; `0.2` for more stringency. Based on Afik et al. (2017) |
| `min_abs_umi` | `1` | Minimum absolute UMI on secondary chain | Raise to `3–5` if using `all_contig_annotations.csv` |
| `make_plots` | `TRUE` | Generate PDF plots | Set `FALSE` for headless/batch runs |

## Input File Format

The pipeline reads the `filtered_contig_annotations.csv` (or `all_contig_annotations.csv`) file produced by **Cell Ranger multi** (v7+) or **Cell Ranger VDJ** (v3+). This is a CSV with one row per contig (not per cell).

### Required columns

| Column | Type | Description |
|--------|------|-------------|
| `barcode` | chr | Cell barcode (e.g., `AAACCTGAGAAACCGC-1`) |
| `is_cell` | lgl/chr | Whether the contig is cell-associated (vs. background) |
| `contig_id` | chr | Unique contig identifier |
| `high_confidence` | lgl/chr | Assembly confidence |
| `length` | dbl | Contig length (bp) |
| `chain` | chr | Chain type: `TRA`, `TRB`, `TRG`, `TRD`, `IGH`, `IGL`, `IGK` |
| `v_gene` | chr | V gene segment (e.g., `TRBV2`) — may be `NA` |
| `d_gene` | chr | D gene segment (only TRB/TRD; `NA` for TRA/TRG) |
| `j_gene` | chr | J gene segment (e.g., `TRBJ1-2`) |
| `c_gene` | chr | Constant gene (e.g., `TRBC1`, `TRAC`) |
| `full_length` | lgl/chr | Whether the contig spans the full V(D)J region |
| `productive` | lgl/chr | Whether the rearrangement is productive (in-frame, no stop codon) |
| `cdr3` | chr | CDR3 amino acid sequence |
| `cdr3_nt` | chr | CDR3 nucleotide sequence |
| `reads` | dbl | Number of reads supporting this contig |
| `umis` | dbl | Number of UMIs supporting this contig |
| `raw_clonotype_id` | chr | Cell Ranger's own clonotype ID |
| `raw_consensus_id` | chr | Cell Ranger's consensus ID |
| `exact_subclonotype_id` | dbl | Cell Ranger's subclonotype ID |

> **Cell Ranger multi vs. VDJ:** Both produce identical column formats. The key difference is that Cell Ranger **multi** produces `filtered_contig_annotations.csv` (recommended) while Cell Ranger **VDJ** may produce both `filtered_` and `all_contig_annotations.csv`. The pipeline accepts either.
